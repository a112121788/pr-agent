# Roadmap

## 北极星

Gitee PR-Agent 是审核工厂的核心机。代码审查不再靠人逐行点头。Agent 自己验证：人在每张拉取请求上点审查，正在审查的不能再同时开一次，不先做意图规划。判定只能是放行、退回或等待，并且只在当前提交已有放行时自动汇入。已经写下双线的拉取请求先拆开。人做抽查。抽查发现的问题用来改规则和环境。

## 版本

产品里程碑用 `0.0.8`、`0.0.9`、`0.1.0`。这不是把 `pyproject.toml` 里的 `0.47.0` 改小。`0.1.0` 是给内部几个人试用的一版，不是公开发布。

### `0.0.8` 装得住

镜像重启后，已登记仓库和审查任务还在。失败的审查变成「失败」，按钮可以再点。驾驶舱能看出自己跑的是哪一次构建。

### `0.0.9` 审得完

在已登记仓库上点「批量审查」，一张真实拉取请求写回中文审查评论。流水线用 Markdown 显示这条评论。审查进行中不会再开一次。

### `0.1.0` 可内测

内测的人按一份说明完成：启动、登记、批量审查、在 Gitee 看到评论。内测默认不调用合并。抽查发现的问题记到规则或环境，不在页面里临时改判定。

## Later

- 意图规划。等拉取请求积压后再做。
- 判定人权限名单。
- 旧版契约和新版契约的自动对照。
- 真实 Webhook 投递核对。

## 质量门槛

- 模型输出不能写入受理意图，也不能直接变成判定。
- 判定和证据都必须带当前 head SHA。SHA 变化后，旧记录失效。
- 只在当前提交已有放行、且不是双线时才调用 Gitee 合并接口。退回、等待、提交变化、双线和意图不明都留给抽查。
- 不新增运行时依赖。

## 风险

- 把审查评论里的“批准”误当成工厂判定。
- 企业版 Gitee 的议题接口可能返回 404，受理不能依赖它一定可读。
- 双线识别若靠模型语义，会误拆正常改动。第一版只用显式声明。
