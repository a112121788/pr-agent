## Overview

`/improve` suggests code changes for the pull request. On Gitee the result is a comment and, when a line can be anchored, inline comments. Gitee cannot commit the suggested code.

Comment on the pull request:

```
/improve
```

Or pass `improve` to the [Gitee CLI image](./index.md#run). The URL must be `https://gitee.com/owner/repo/pulls/N` or `https://e.gitee.com/<enterprise>/repos/owner/repo/pulls/N`.

An opened pull request runs `/improve` with `/describe` and `/review`, unless `gitee.pr_commands` replaces that list.

## What is published

The summary heading is `pr_code_suggestions.suggestions_heading`, which defaults to `PR 代码建议`. The suggestion text follows `config.response_language` = `zh-CN`.

`pr_code_suggestions.committable_code_suggestions` defaults to `false`, so suggestions are collected in that one comment. Setting it to `true`, or setting `pr_code_suggestions.dual_publishing_score_threshold` above `-1`, still does not create a commit on Gitee. Those modes only change which comments and inline comments are posted. Inline comments use Gitee's diff `position`, counted from the line below the first `@@` hunk header. A suggestion that cannot be placed stays in the summary comment.

`pr_code_suggestions.persistent_comment` is `true`, so a later summary replaces the previous `PR 代码建议` comment.

`/review` and `/improve` were run on [eclouddev/hlzs_web#2896](https://gitee.com/eclouddev/hlzs_web/pulls/2896).

Each suggestion has a one-line summary, a longer explanation, and a before/after snippet. Treat the snippet as an illustration. Apply it yourself after you agree with the finding. Gitee PR-Agent will not push the change.

## How many suggestions

A diff is split into chunks of about `config.max_model_tokens` tokens (default `32000`). Each chunk asks for up to `pr_code_suggestions.num_code_suggestions_per_chunk` suggestions (default `3`). `pr_code_suggestions.max_number_of_calls` (default `3`) caps the number of chunks.

`pr_code_suggestions.max_suggestions_per_file` defaults to `0`, which means no per-file cap. Set a positive integer to keep only the highest-scored suggestions for each file after the chunks are merged.

`pr_code_suggestions.suggestions_score_threshold` defaults to `0`. A suggestion scored below the threshold is dropped. Values above 7 or 8 often drop useful notes.

While chunks run, and when `config.publish_output_progress` is enabled, the progress comment is updated in place and removed before the final comment.

If some chunks fail, later entries in `config.fallback_models` are tried for the failed chunks only. The configured fallback is `glm-5.3`. Successful chunks are kept. If every chunk fails, the command fails.

## Extra instructions and repo files

`pr_code_suggestions.extra_instructions` changes this command's prompt. `config.repo_context_files` adds files such as `AGENTS.md` from the default branch (`config.repo_context_from_default_branch` is `true`). Set that flag to `false` to read the pull request's target branch instead. The rendered context stops at `config.repo_context_max_lines` (default `500`).

```toml
[pr_code_suggestions]
extra_instructions = """\
Focus on data-loss and auth checks.
Do not suggest formatting-only edits.
"""
focus_only_on_problems = true

[config]
repo_context_files = ["AGENTS.md", "best_practices.md"]
```

`focus_only_on_problems` defaults to `true`, so suggestions prefer defects over style.

A self-review checkbox (`pr_code_suggestions.demand_code_suggestions_self_review`) is only a visual marker. Ticking it does not approve the pull request or hide suggestions.

## Configuration

| Key | Default | Effect |
|-----|---------|--------|
| `suggestions_heading` | `PR 代码建议` | Summary comment heading. |
| `committable_code_suggestions` | `false` | Also post inline comments. Still no commit on Gitee. |
| `dual_publishing_score_threshold` | `-1` | Also post inline comments at or above this score. `-1` disables it. |
| `persistent_comment` | `true` | Edit the previous summary comment. |
| `focus_only_on_problems` | `true` | Prefer defects over style. |
| `suggestions_score_threshold` | `0` | Drop suggestions below this score. |
| `num_code_suggestions_per_chunk` | `3` | Suggestions requested per chunk. |
| `max_suggestions_per_file` | `0` | Per-file cap after merging. `0` means no cap. |
| `max_number_of_calls` | `3` | Maximum chunks. |
| `publish_output_no_suggestions` | `true` | Still comment when there is nothing to suggest. |
| `enable_suggestions_coverage_footer` | `true` | List failed chunks and files left out of the budget. |
| `extra_instructions` | empty | Extra directions for this command. |
| `enable_help_text` | `false` | Add help text to the comment. |

The deprecated spelling `commitable_code_suggestions` still enables inline comments and logs a warning. Rename it to `committable_code_suggestions`.
