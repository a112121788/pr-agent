## 概述

`/describe` 会写出拉取请求的类型、摘要、文件导览，以及一张可选的 Mermaid 图。响应语言是 `zh-CN`。

在拉取请求上评论：

```
/describe
```

也可以把 `describe` 传给 [Gitee CLI 镜像](./index.md#run)。拉取请求 URL 必须是 `https://gitee.com/owner/repo/pulls/N` 或 `https://e.gitee.com/<enterprise>/repos/owner/repo/pulls/N`。

拉取请求打开时会同时运行 `/describe`、`/review` 和 `/improve`，除非 `gitee.pr_commands` 另有指定。参见 [Gitee 安装](../installation/gitee.md)。

需要时把覆盖参数写在命令上：

```
/describe --pr_description.extra_instructions="focus on the API change"
```

## 文本发到哪里

默认 `pr_description.publish_description_as_comment` 为 `false`，因此工具会替换拉取请求正文。设为 `true` 则改为发一条评论。`pr_description.publish_description_as_comment_persistent` 保持 `true` 时，之后的运行会编辑这条评论。

`pr_description.generate_ai_title` 为 `false`，现有标题会保留。设为 `true` 才会替换标题。

`pr_description.add_original_user_description` 为 `true`。`PR Type` 标题以上的文字会当作作者原文保留。该标题以下的文字会被视为上一次生成的描述并被替换。请在命令运行前写好作者原文。命令还在跑时修改正文，可能把原文弄丢。

`pr_description.publish_labels` 为 `false`，所以除非打开它，`/describe` 不会打标签。只需要标签时用 [`/generate_labels`](./generate_labels.md)。

## 图和导览

`pr_description.enable_pr_diagram` 为 `true`。变更没有可用流程时会省略这张图。`pr_description.pr_diagram_direction` 为 `adaptive`：节点链长于 `pr_description.pr_diagram_direction_threshold`（默认 `5`）时改为自上而下。把方向设为 `LR` 或 `TD` 可以固定它。

`pr_description.enable_semantic_files_types` 为 `true`，会加入文件导览。`pr_description.collapsible_file_list` 为 `adaptive`，文件数超过 `pr_description.collapsible_file_list_threshold`（默认 `6`）后列表会折叠。

`pr_description.enable_large_pr_handling` 为 `true`。大 diff 会拆成多次模型调用再合并。启用 `config.publish_output_progress` 时，占位评论会就地更新。

## 标记

把 `pr_description.use_description_markers` 设为 `true`，用来填充正文里已经写好的标记：

```
## PR Type:
pr_agent:type

## PR Description:
pr_agent:summary

## PR Walkthrough:
pr_agent:walkthrough

## PR Diagram:
pr_agent:diagram
```

`pr_agent:type`、`pr_agent:summary`、`pr_agent:walkthrough` 和 `pr_agent:diagram` 会被换成对应段落。关闭图时 `pr_agent:diagram` 保持为空。启用标记但正文里一个都没有时，描述不会被改动。

`pr_description.include_generated_by_header` 为 `true`，生成的标记段落可以带上 `Generated by PR Agent at ...` 头。

## 自定义标签

内置类型名是 `Bug fix`、`Tests`、`Enhancement`、`Documentation` 和 `Other`。要加仓库自己的名字，先启用自定义标签，并把每条说明写成条件：

```toml
[config]
enable_custom_labels = true

[custom_labels."sql_changes"]
description = "Use when a PR contains changes to SQL queries"
```

令牌能编辑标签时，标签通过 Gitee API 发布。模型在这组名字之外编造的名称会被丢掉。已经由人加上的标签会保留。

## 配置

| 键 | 默认值 | 作用 |
|----|--------|------|
| `publish_labels` | `false` | 把生成的标签打到拉取请求上。 |
| `publish_description_as_comment` | `false` | 发评论，而不是替换正文。 |
| `publish_description_as_comment_persistent` | `true` | 编辑上一条描述评论。 |
| `add_original_user_description` | `true` | 保留 `PR Type` 以上的作者原文。 |
| `generate_ai_title` | `false` | 为 `true` 时替换标题。 |
| `enable_pr_type` | `true` | 包含类型段落。 |
| `enable_pr_description` | `true` | 包含摘要。其他段落不受影响。 |
| `enable_pr_diagram` | `true` | 适用时包含 Mermaid 图。 |
| `pr_diagram_direction` | `adaptive` | `adaptive`、`LR` 或 `TD`。 |
| `enable_semantic_files_types` | `true` | 包含文件导览。 |
| `use_description_markers` | `false` | 填充 `pr_agent:` 标记，而不是重写正文。 |
| `enable_large_pr_handling` | `true` | 把大 diff 拆成多次模型调用。 |
| `extra_instructions` | 空 | 只给这条命令的额外说明。 |
| `final_update_message` | `true` | 描述更新后发一条短通知。 |

这些键都属于 `[pr_description]`。
