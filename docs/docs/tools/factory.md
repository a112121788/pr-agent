---
title: "审核记录"
sidebar_position: 5
---

审核记录把一张拉取请求分成四段。Gitee PR-Agent 保存记录，不代替人做判定，也不按下合并。

## 受理

提出人写明这张请求属于哪一类：

```text
/intake 新业务 增加出科确认
```

只接受 `新业务`、`旧版迭代`、`新版升级`、`双线`。后面的文字原样保存。非法意图不会发布评论。

## 取证

`/review` 和 `/improve` 的最终评论以当前提交号开头：

```text
提交号：abc123456789
```

提交变化后，旧评论不再代表当前改动。

## 判定

负责人只写三个词之一：

```text
/verdict 放行
/verdict 退回
/verdict 等待
```

评论包含判定、提交号和判定人。审查正文里的“批准”“请求修改”“仅评论”不是判定。

## 汇入检查

```text
/merge-check
```

只有最新判定是“放行”，并且它的提交号等于当前提交时，结果才是“可以由人合并”。缺少判定、提交已变化、判定为退回或等待时，结果都是“不能汇入”。

这条命令不调用 Gitee 合并接口。合并仍由有权限的人在 Gitee 页面上点击。

## 双线

`/intake 双线 ...` 之后，`/review` 会增加一条阻塞项：先拆成两张拉取请求。普通描述里出现“同时改旧字段和新汇总”不会被自动猜成双线。
