## 概述

有两种情形：

1. 拉取请求足够小，可以放进单条提示词（包括系统提示词和用户提示词）
2. 拉取请求太大，无法放进单条提示词（包括系统提示词和用户提示词）

两种情形都会先使用以下策略

#### 仓库语言优先级策略

我们根据以下标准对仓库语言排序：

1. 排除二进制文件和非代码文件（例如图片、pdf 等）
2. 给定仓库中使用的主要语言
3. 按仓库中最常见的语言对拉取请求文件排序（降序）：
   * ```[[file.py, file2.py],[file3.js, file4.jsx],[readme.md]]```

### 小型拉取请求

此时可以把整个拉取请求放进单条提示词：

1. 排除二进制文件和非代码文件（例如图片、pdf 等）
2. 把每个补丁周围的上下文扩展为补丁上下各 3 行

### 大型拉取请求

#### 动机

拉取请求可能非常长，包含大量信息，且与 pr-agent 的相关程度各不相同。
我们希望在单条 LMM 提示词中装入尽可能多的信息，同时保持这些信息与 pr-agent 相关。

#### 压缩策略

我们优先保留新增，而不是删除：

* 把所有已删除文件合并为一个列表（`deleted files`）
* 文件补丁是差异块列表，从文件补丁的差异块中移除所有仅删除类型的差异块

#### 自适应且感知令牌的文件补丁装入

我们使用 [tiktoken](https://github.com/openai/tiktoken) 对上述修改后的补丁分词，并使用以下策略把补丁装入提示词：

1. 在每种语言内，按文件中的令牌数对文件排序（降序）：
    * ```[[file2.py, file.py],[file4.jsx, file3.js],[readme.md]]```
2. 按上述顺序遍历补丁
3. 把补丁加入提示词，直到提示词距离最大令牌长度还留有一定缓冲
4. 如果仍有补丁剩余，把剩余补丁作为名为 `other modified files` 的列表加入提示词，直到提示词达到最大令牌长度（硬停止），跳过其余补丁。
5. 如果尚未达到最大令牌长度，把 `deleted files` 加入提示词，直到提示词达到最大令牌长度（硬停止），跳过其余补丁。
